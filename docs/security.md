# Security Controls (implemented) & Honest Gaps

Implemented: invitation-only auth; bcrypt-12; single-use hashed invite tokens; role checks server-side on every route AND every server action; client isolation by session-derived clientId with 404 on foreign IDs (no info leak); middleware outer gate on /portal/* and /api/portal/*; upload validation server-side (extension allow-list, MIME cross-check, magic-byte content sniffing, 25MB cap, NUL-scan for CSV, path-traversal-proof filename sanitising, executables impossible by construction); per-user upload and login rate limiting; generic client-facing errors with details only in server logs; audit trail for security events (never contents/passwords/tokens); portal pages noindex; no analytics inside the portal; secrets only in env vars; `.env` git-ignored.

Honest gaps / to review formally: rate limiting is per-serverless-instance (swap to a shared store for hard guarantees); no malware scanning yet (hook point exists in the upload pipeline — add e.g. a scanning API before Drive placement); no 2FA yet; CSRF relies on Auth.js + same-site cookies + server actions' built-in origin checks; no formal penetration test; GDPR documentation is a data map, not a compliance certification.
